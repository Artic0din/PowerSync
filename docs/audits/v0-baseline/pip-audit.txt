  The audit's C2 finding ("CVEs reachable under current minimum bounds")
  was based on WebSearch results listing historical CVEs for each package.
  Those CVEs exist for OLD versions of the packages but the `>=` resolver
  picks current versions on fresh install, not the minimum-bound version.

  C2 is therefore largely REFUTED as a #15 security finding.

  It remains a #5 dependency-management concern: loose minimum-bound pins
  do not enforce upgrades for existing installations. A user who installed
  18 months ago and never updated would have an old aiohttp. The risk is
  drift, not exposure.

  Recommendation: tighten to a range like aiohttp>=3.13.3,<4.0 to enforce
  patched-version floors without admitting future major-version breakage.
