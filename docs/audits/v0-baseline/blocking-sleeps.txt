Blocking asyncio.sleep ≥ 60s — V0.6
====================================
Run date: 2026-05-27

Command (extended-regex mode required; basic regex does not support
alternation, and the threshold must exclude 10-59):

  grep -rnE "asyncio\.sleep\(([6-9][0-9]|[1-9][0-9]{2,})\)" \
       custom_components/power_sync/

Pattern explanation:
  [6-9][0-9]      — matches 60-99
  [1-9][0-9]{2,}  — matches 100, 1000, etc. (3+ digit positive)
  Combined: any sleep ≥ 60 (and ≤ 99) OR ≥ 100.

Constitution principle: #18 (performance — no blocking main-thread work),
#19 (platform conventions — HA event loop discipline).

asyncio.sleep is not literally blocking (it yields to the event loop),
but a 60s+ sleep inside a coordinator/handler still:
  - holds the coroutine task alive for that duration
  - delays shutdown if HA restarts during the sleep
  - may indicate a missing event-driven pattern (callback registration
    via async_call_later, time_pattern triggers, or coordinator
    update_interval)

Recommendation per-site:
  __init__.py:16814 — read context; likely a retry backoff. Consider
    capping to <30s or moving to call_later.
  optimization/ev_coordinator.py:218,224 — replace with scheduled callback.
  optimization/coordinator.py:2025 — same.
